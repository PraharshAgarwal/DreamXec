RBAC Engine Spec DreamXec Phase-2

Role Onboarding & Verification Guide

This document outlines the step-by-step workflow, verification logic, database transitions, and role privileges for every user role within the DreamXec multi-tenant Research ERP ecosystem.

Role: RESEARCHER

1. Student Researcher Onboarding

UserOrg.role = RESEARCHER
Step 1

Signup & Domain

User registers and enters academic email (.edu). System validates email domain matches whitelisted university pattern.

DB Updates: User.emailVerified = true
User.accountStatus = ACTIVE
Step 2

Academic Profile

Selects university, department, and uploads active Student ID card/Enrollment scan. Set profile fields.

DB Updates: StudentVerification = PENDING
User.studentVerified = false
Step 3

Admin Approval

University Registrar Admin reviews uploaded ID/Document in approval queue. Verification confirmed.

DB Updates: StudentVerification = APPROVED
User.studentVerified = true
Step 4

Scope Unlocked

Links student to University. Unlocks public dashboards, shared lab infrastructure access, and project team messaging.

DB Updates: UserOrg.role = RESEARCHER
UserOrg.verified = true
Role: PROFESSOR

2. Professor / PI Onboarding

UserOrg.role = PROFESSOR
Step 1

Faculty Input

Register with official research email, selected department, and ORCID iD for publication mapping.

DB Updates: User.emailVerified = true
User.orcid = orcid_id
Step 2

Accreditation Upload

Upload scan of official employment contract or faculty appointment letter. Linked to University Admin approval log.

DB Updates: UserOrg.verified = false
UserOrg.role = PROFESSOR
Step 3

Registrar Audit

University Registrar manually audits employment scan and matches ORCID index records.

DB Updates: AuditLog.status = AUDITED
AuditLog.action = FACULTY_VERIFY
Step 4

Active PI Scope

Approved. Unlocks project stage-gate oversight, signing off on lab notebooks, and grant Principal Investigator roles.

DB Updates: UserOrg.verified = true
User.role = USER (Global)
Role: INCUBATOR_MANAGER

3. Incubator Manager Onboarding

UserOrg.role = INCUBATOR_MANAGER
Step 1

Admin Invitation

Invited directly via secure email token sent by the university or corporate tenant's Admin.

DB Updates: User.accountStatus = ACTIVE
InviteToken.used = true
Step 2

Incubator Setup

Accepts token invitation and links profile to the parent organization's incubation division.

DB Updates: UserOrg.role = INCUBATOR_MANAGER
UserOrg.verified = true
Step 3

Idea Board Active

Verification complete. Unlocks idea pipeline evaluations (Novelty/Feasibility scoring), mentoring logs, and commercialization stats.

DB Updates: UserOrg.verified = true
UserOrg.permissions = [SCORE_IDEAS]
Role: DONOR

4. Donor & Sponsor Onboarding

User.role = DONOR
Step 1

Biz Profile Setup

Corporate user registers using official corporate email domain (e.g. @google.com, @stripe.com).

DB Updates: User.role = DONOR
User.emailVerified = true
Step 2

Legal Registry

Inputs Company GSTIN/EIN registry numbers, corporate tax documents, and address details. Status set to review.

DB Updates: Donor.verified = false
Donor.gstin = tax_number
Step 3

Platform Audit

Platform Super-Admin verifies corporate standing against public registry databases manually.

DB Updates: Donor.accountStatus = ACTIVE
AuditLog.action = DONOR_VERIFY
Step 4

Grant Posting Active

Corporate identity confirmed. Unlocks grant directory creations, proposal reviews, and milestone payout gates.

DB Updates: Donor.verified = true
Donor.permissions = [POST_GRANT]
Role: COMPLIANCE_OFFICER

5. Compliance Officer Onboarding

UserOrg.role = COMPLIANCE_OFFICER
Step 1

Direct Invite Only

No self-registration. Created exclusively via a security token sent by the university or platform admin.

DB Updates: User.accountStatus = ACTIVE
InviteToken.used = true
Step 2

Board Accreditation

Officer inputs compliance committee details and signs off on compliance board rules.

UserOrg.role = COMPLIANCE_OFFICER
UserOrg.verified = false
Step 3

IRB Board Active

Verified. Action logs recorded in system AuditLog. Unlocks IRB protocol submissions, approvals, and risk reviews.

DB Updates: UserOrg.verified = true
AuditLog.action = IRB_OFFICER_ACTIVATE
