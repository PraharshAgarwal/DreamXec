DAY 1
Platform Overview, Tech Stack & Dev Environment Setup
Module 1 · Foundation · ~8 hours
🎯 Module 1A: Understanding DreamXec
  • What is DreamXec? — A social impact platform connecting students, colleges, donors, NGOs, corporates, and incubators to fund & execute research-driven campaigns
  • Key user roles: Student, Donor, Org Admin, Mentor, Professor, Researcher, Compliance Officer, DX Platform Admin
  • Core product features: Campaign creation & funding, multi-org hierarchy, onboarding workflows, donation ledger, verification pipeline, vault system
  • Read the ARCHITECTURE_HANDBOOK.md — Sections 1-5 (Trade-offs, Caching, RLS, Zanzibar, Onboarding)
  • Read SERVICE_ARCHITECTURE.md — All 12 microservice descriptions
🛠️ Module 1B: Development Environment Setup
  • Clone the monorepo and understand the folder structure: client/, server/, server/prisma/
  • Install Node.js (v20+), npm, Git, VS Code with recommended extensions (Prisma, ESLint, Prettier, Tailwind IntelliSense)
  • Set up server/.env using .env.example — configure DATABASE_URL, REDIS_URL, JWT secrets, Cloudinary, SendGrid keys
  • Run npm install in both client/ and server/
  • Run npx prisma generate in server/ to generate the Prisma client
  • Start backend: npm run dev in server/ (runs on port 5000 with nodemon)
  • Start frontend: npm run dev in client/ (runs on port 5173 with Vite)
  • Verify API health: hit GET /api/health and confirm the frontend loads the homepage
📚 Module 1C: Topics to Learn
  • Git Fundamentals: branching, merging, pull requests, commit message conventions
  • JavaScript/TypeScript Basics: ES6+ syntax, async/await, destructuring, modules, type annotations
  • Node.js Event Loop: Understanding non-blocking I/O, event-driven architecture
  • Package Managers: npm scripts, lockfiles, dependency management in a monorepo

DAY 2
Database Schema, Prisma ORM & Multi-Schema Architecture
Module 2 · Backend Core · ~8 hours
🗄️ Module 2A: PostgreSQL & Multi-Schema Design
  • Understand DreamXec's 14 PostgreSQL schemas: identity, organization, workflow, verification, finance, payments, documents, notifications, audit, search, jobs, campaigns, doc_vault, account_vault
  • Study key models in server/prisma/schema.prisma: User, Organization, Membership, Session, Campaign, Donation, WorkflowTemplate, WorkflowInstance, LedgerAccount
  • Understand enum types: Role, OrgRole, OrgType, LifecycleStatus, MembershipStatus, StageType, ExecutionStatus
  • Learn about UUID primary keys, composite unique constraints, and cascade delete strategies
  • Study the Organization hierarchy model — parentId, ancestorId, depth, hierarchyPath (ltree concept)
🔧 Module 2B: Prisma ORM Deep Dive
  • Prisma schema language: models, relations, enums, @@map, @map, @@schema directives
  • Prisma Client API: findUnique, findMany, create, update, upsert, delete
  • Nested writes and includes: eager loading relations (e.g., User with memberships)
  • Prisma migrations: npx prisma migrate dev, npx prisma migrate status
  • Prisma Studio: npx prisma studio for visual database browsing
  • Study how the project initializes Prisma in server/src/config/prisma.js
📚 Module 2C: Topics to Learn
  • SQL Fundamentals: SELECT, JOIN, WHERE, GROUP BY, aggregate functions
  • PostgreSQL Specifics: JSONB columns, UUID generation, TIMESTAMPTZ, indexing strategies
  • Schema Design: Normalization (3NF), denormalization trade-offs, foreign keys, constraints
  • ORM Patterns: Repository pattern, data mappers, query builders vs raw SQL

DAY 3
Authentication, JWT, OAuth & Session Management
Module 3 · Security · ~8 hours
🔐 Module 3A: Auth Architecture in DreamXec
  • Study the auth module: server/src/modules/auth/ — auth.service.js, auth.validation.js, auth.mapper.js
  • JWT token flow: generation (login/signup → sign JWT → return token), validation (middleware extracts from Authorization header)
  • Password hashing with bcryptjs: hashing on registration, comparison on login
  • OAuth flow: Google OAuth via passport-google-oauth20 → callback → JWT issuance
  • Email verification: token generation, SendGrid email dispatch, verification endpoint
  • Password reset flow: forgot password → OTP/token → reset endpoint with expiry validation
  • Session management: express-session with optional Redis store via connect-redis
🔑 Module 3B: Auth Middleware
  • Study server/src/middleware/auth.middleware.js — the JWT extraction and verification logic
  • How the middleware attaches req.user for downstream controllers
  • Token expiry handling and error responses (401 Unauthorized)
  • The dev token utility at /dev/gen-token for local testing
📚 Module 3C: Topics to Learn
  • JWT Deep Dive: Header, Payload, Signature, RS256 vs HS256, expiry claims
  • OAuth 2.0 Protocol: Authorization Code flow, scopes, tokens, callback URIs
  • Password Security: Salted hashing, bcrypt cost factor, timing attacks
  • Session vs Token Auth: Stateful (sessions) vs stateless (JWT), cookie security, CSRF prevention
  • Middleware Pattern: Express middleware chain, next(), error middleware

DAY 4
Permissions Engine — RBAC, ABAC & Multi-Tenancy
Module 4 · Access Control · ~8 hours
🛡️ Module 4A: Permission Architecture
  • Study server/src/permissions/matrix.js — the RBAC permission matrix mapping permissions to allowed roles
  • Understand the dual-role system: global roles (USER, ADMIN) + org-scoped roles (STUDENT, ORG_ADMIN, DONOR, PROFESSOR, MENTOR, etc.)
  • ABAC (Attribute-Based Access Control): evaluateABACRules() — resource ownership checks, faculty access rules
  • Multi-tenancy enforcement: canUserPerformAction() — tenant-scoped permission checks with orgId context
  • DX Platform admin checks — dx:-prefixed permissions scoped to the DX system org slug
  • Study server/src/middleware/permission.middleware.js — how routes are protected
  • Study server/src/permissions/permission.service.js — seeding permissions from the matrix into the database
🏢 Module 4B: Multi-Tenancy & Organization Hierarchy
  • Org hierarchy: parentId/ancestorId/depth model in the Organization table
  • Membership model: how users belong to organizations with specific OrgRoles
  • Profile switching: active profile, identity types (USER, ORG_MEMBER, ORG_ADMIN)
  • Study the auth mapper: how login response includes availableProfiles, activeProfile, and computed permissions
  • Understand DX Admin vs Org Admin: DX admins manage the platform, Org admins manage their institution
📚 Module 4C: Topics to Learn
  • RBAC (Role-Based Access Control): Roles → Permissions mapping, role hierarchies
  • ABAC (Attribute-Based Access Control): Subject, resource, action, and environment attributes
  • Multi-Tenancy Patterns: Shared schema with tenant isolation (RLS), tenant-scoped queries
  • Zanzibar ReBAC (Concept): Google's relationship-based access control model (as described in ARCHITECTURE_HANDBOOK.md)

🧪 Testing Project 4: Permission Matrix Validator

  • Tests at least: STUDENT creating a project (allowed), STUDENT accessing admin (denied), ORG_ADMIN managing members (allowed), DONOR allocating grants (allowed with context)
  • Tests ABAC rules: resource owner vs non-owner access

Campaigns, Donations, Razorpay & Ledger System
Module 7 · Finance · ~8 hours
📣 Module 7A: Campaign System
  • Study the campaign module: server/src/modules/campaigns/ — routes, controllers, services, mappers, validation
  • Campaign lifecycle: DRAFT → PENDING_REVIEW → ACTIVE → FUNDED → COMPLETED
  • Frontend components: CreateCampaign.tsx, CampaignDetails.tsx, MyCampaigns.tsx, BrowseCampaigns.tsx
  • Campaign features: milestones, endorsements, team members, comments, funding progress

  • Study server/src/modules/donations/ — donation.service.js, donation.repository.js, payment routes
  • Razorpay integration: order creation → client-side Razorpay checkout → webhook verification
  • Donation flow in AppRoutes.tsx: handleDonate() function with Razorpay SDK loading

📒 Module 7C: Double-Entry Ledger
  • Study server/src/services/ledger.service.js — the financial accounting engine
  • Double-entry principles: every transaction creates DEBIT + CREDIT entries summing to zero
  • Ledger accounts: donor wallets, campaign escrow, organization payouts
  • Disbursement service: disbursement.service.js — milestone-based fund release
  • Vault system: server/src/modules/vault/ — secure document and account vaults

  • Double-Entry Accounting: Debits, credits, account types (asset, liability, equity)

  • Escrow Patterns: Holding funds until milestone verification

🌐 Module 8A: Express API Architecture
  • Study server/server-app.js — the full Express app setup: CORS, sessions, middleware chain, route mounting

  • cache.middleware.js — Redis response caching
  • organization.middleware.js — tenant context extraction
  • upload.middleware.js — Multer file upload handling

📚 Module 8C: Topics to Learn
  • RESTful API Design: Resource naming, pagination, filtering, sorting, error response format
  • Express Middleware Pattern: Request lifecycle, middleware ordering, error propagation
  • Input Validation: Zod schemas, Joi validators, sanitization, error messages
